# Remaining cupy failures: cupy indexers on numpy objects, basic assignment, bool()

_Opened by @headtr1ck on 2026-10-15_

Labels: bug, topic-indexing, topic-arrays

### What happened?

While reviewing #11735 (0d cupy indexers, #8820) I ran xarray's cupy code paths on a GPU and found three more failures on current main. None are caught by CI, since it has no GPU.

**1. Indexing numpy-backed objects with cupy indexers.** A cupy indexer that reaches a pandas index or a numpy array fails with cupy's implicit conversion error. This affects any DataArray with a dimension coordinate, and also the common `da.isel(x=da.argmax("x"))` pattern:

```python
import cupy as cp
import xarray as xr

da = xr.DataArray(cp.arange(24).reshape(4, 6), dims=["x", "y"], coords={"x": [10, 20, 30, 40]})
da.isel(x=cp.array([1, 2]))  # TypeError: Implicit conversion to a NumPy array is not allowed (PandasIndex.isel, xarray/core/indexes.py)
da.isel(x=da.argmax("x"))    # same error (PandasIndexingAdapter._index_get, xarray/core/indexing.py)
```

**2. Assigning to cupy data with basic indexers.** Assigning with an int, a slice or `.loc` fails, while a list works:

```python
a = xr.DataArray(cp.arange(24).reshape(4, 6), dims=["x", "y"])
a[dict(x=2)] = -1      # AttributeError: 'Flags' object has no attribute 'writeable'
a[dict(x=[0, 1])] = -1  # works
```

The underlying error is cupy's `ValueError: non-scalar numpy.ndarray cannot be used for fill`, since the value arrives as a 0d numpy array. `NumpyIndexingAdapter._safe_setitem` then hides it by checking `array.flags.writeable`, which cupy's flags don't have.

**3. `bool()` of a 0d cupy DataArray.** `DataArray.__bool__` goes through `.values`, i.e. `np.asarray`:

```python
bool(xr.DataArray(cp.array(True)))  # TypeError, while bool(cp.array(True)) works
```

This is why `idxmax`/`idxmin(skipna=True)` fail with cupy (`if ... allna.any()` in `_calc_idxminmax`), and why `test_duck_array_wrapping.py::TestDataArrayMethods::test_idxmax[True-cupy]` / `test_idxmin[True-cupy]` fail when run on a GPU.

### What did you expect to happen?

The same results as with numpy, with the data staying on the device.
