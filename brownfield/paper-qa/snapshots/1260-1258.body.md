# UnicodeEncodeError when indexing PDFs with surrogate characters in extracted text

_Opened by @hummat on 2025-12-30_

Labels: bug

## Description

PaperQA2 crashes with `UnicodeEncodeError` when indexing certain PDFs that contain mathematical symbols which extract as invalid Unicode surrogate characters.

## Error


## Root Cause

Some PDFs (especially those with mathematical notation) use custom fonts with character mappings that pypdf cannot translate to valid Unicode. The extracted text contains orphaned UTF-16 surrogate characters (e.g., `\udc63`, `\udc65`, `\udc66`) which are invalid in UTF-8.

Example from affected PDF (arXiv:1711.07566 "Neural 3D Mesh Renderer"):
```python
# Page 2 extracted text contains:
'\udc63" = (\udc65", \udc66")\n\udc43*\t, \udc3c*(\udc65")'
# These should be mathematical italic characters (𝑐, 𝑥, 𝑦, 𝑃, 𝐼)
```

## Suggested Fix

In `paperqa/utils.py`, the `hexdigest` function should sanitize the text before encoding:

```python
def hexdigest(data: str | bytes) -> str:
    if isinstance(data, str):
        # Replace invalid surrogates with replacement character
        data = data.encode("utf-8", errors="surrogateescape").decode("utf-8", errors="replace").encode("utf-8")
    return hashlib.sha256(data).hexdigest()
```

Or more simply:
```python
def hexdigest(data: str | bytes) -> str:
    if isinstance(data, str):
        data = data.encode("utf-8", errors="replace")
    return hashlib.sha256(data).hexdigest()
```
